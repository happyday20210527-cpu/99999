# Kilo Code(終端機版)— 自動核准設定 + 閒置自動催促腳本

這份文件是回應「把這台電腦的 Kilo Code 設成 auto,只有『刪除檔案』跟『影響系統
穩定性』這兩類操作不開放權限,其他都讓它自己搞定」這個需求所準備的說明。

> **重要前提說明**:這次是在雲端的 Claude Code 作業環境中準備這些檔案,
> 這個雲端環境**無法連線到你的實體筆電**,也**無法連線到 kilo.ai 官網**
> 逐一核對你目前實際安裝版本的畫面/指令是否完全一致。也就是說,以下設定
> 是依照 Kilo Code 官方文件/原始碼架構所推斷出的最佳建議版本,
> **並不是我已經在你電腦上按下去生效了** —— 需要你在自己的電腦上,
> 依照下面步驟把設定套用上去,或是把這兩個檔案複製到你的筆電後執行。

---

## 1. 你這台電腦用的是「終端機(CLI)版本」的 Kilo Code

確認方式(在你的終端機打):

```powershell
kilo --version
```

以下步驟都是針對 CLI 版本,不是 VS Code 擴充套件版本。

---

## 2. 套用「自動核准」設定(除了刪除檔案、系統穩定性以外都自動放行)

檔案:`kilocode-auto-approve-settings.jsonc`

Kilo Code CLI 使用 `kilo.jsonc` 這個設定檔控制每個工具的核准方式,
每個項目的值只能是三選一:

| 值 | 意思 |
|---|---|
| `allow` | 直接允許,不會跳出來問你 |
| `ask` | 每次都會詢問 |
| `deny` | 直接擋掉,不會執行 |

### 套用步驟

1. 找到你的 `kilo.jsonc` 位置,通常會是下面其中一個(實際位置請以你安裝版本
   的說明/`kilo --help` 為準):
   - 專案層級:`<專案資料夾>\.kilocode\kilo.jsonc`
   - 全域層級:`%USERPROFILE%\.kilocode\kilo.jsonc`(或 `%USERPROFILE%\.config\kilo\kilo.jsonc`)
2. 如果檔案不存在,可以直接把 `kilocode-auto-approve-settings.jsonc` 複製過去
   並改名成 `kilo.jsonc`。
3. 如果檔案已經存在、裡面已經有其他設定,**不要整檔覆蓋**,而是把
   `kilocode-auto-approve-settings.jsonc` 裡的 `"permission"` 區塊內容,
   合併貼進你原本的 `kilo.jsonc` 對應位置。
4. 存檔後,重新啟動 `kilo`,讓新設定生效。

### 這份設定做了什麼

- **允許自動核准(不用問)**:讀檔、搜尋(glob/grep/list)、瀏覽網頁、
  寫入/編輯檔案內容、使用 skill、使用子任務(task)、以及**大部分**終端機指令。
- **刪除檔案類指令 → 一律擋掉(deny)**,包括:`rm`、`del`、`erase`、
  `Remove-Item`、`rd`/`rmdir`、`rimraf`、`unlink` 等,以及 `git clean`、
  `git reset --hard`、`git push --force`、`git branch -D` 這類「會讓已完成的
  工作消失」的操作(設為 `ask`,而非直接放行)。
- **可能影響系統穩定性的指令 → 擋掉或改為詢問**,包括:磁碟分割/格式化
  (`format`、`diskpart`、`Clear-Disk`、`Remove-Partition`)、開機設定
  (`bcdedit`)、關機/重開機(`shutdown`、`Restart-Computer`)、
  安全性原則(`Set-ExecutionPolicy`)、系統功能開關
  (`Disable-WindowsOptionalFeature`)、服務/防火牆設定
  (`sc.exe`、`Stop-Service`、`netsh advfirewall`)等。
- **專案資料夾以外的路徑(`external_directory`)→ 設為 `ask`**,
  避免任務不小心動到專案以外、跟這次任務無關的檔案。

> 這份清單已盡量涵蓋常見的刪除/破壞性/系統設定類指令,但**不保證涵蓋所有
> 可能寫法**(例如指令別名、包裝腳本等)。建議你實際使用一陣子後,
> 如果發現有漏網的指令被自動允許了,再把它加進 `"bash"` 區塊裡設成
> `"deny"` 或 `"ask"` 即可 —— 規則是由上到下比對,**後面的規則會蓋過
> 前面的**,所以把例外規則放在 `"*": "allow"` 之後即可生效。

## 3. 閒置自動催促腳本(每 15 分鐘檢查一次)

檔案:`kilo-auto-nudge.ps1`

對應需求:「每十五分鐘去問 Kilo Code 任務還在執行嗎,如果回答執行中就不用理它,
如果回答等指示/原地待命,就直接去催它快動作」。

### 這支腳本怎麼運作

Kilo Code CLI **目前沒有官方文件記載的「查詢任務狀態」指令**可以讓外部腳本
直接問它「你現在是執行中還是等待中?」,所以這支腳本改用比較穩妥的做法:

1. 由這支腳本本身負責啟動 `kilo run ...` 這個任務(而不是你自己先手動開一個
   視窗跑,腳本再去外面猜是哪個視窗) —— 這樣腳本才能直接、乾淨地接管它的
   輸入/輸出,不需要用「模擬按鍵去點畫面」這種容易點錯視窗、風險較高的方式。
2. 持續讀取 kilo 的輸出畫面(一樣會即時顯示在你的終端機裡,也會存一份
   log 檔),記錄「最後一次有新輸出的時間」。
3. 每 15 分鐘檢查一次:
   - 最近 15 分鐘內有新輸出 → 視為「執行中」→ 不理它
   - 最近 15 分鐘內完全沒有新輸出 → 視為「等指示/原地待命」→
     自動送一句「請繼續完成任務,不需要等待確認…」進去催它

### 使用方式

```powershell
# 基本用法(用一般核准流程,遵守 kilo.jsonc 裡的 allow/ask/deny 設定)
.\kilo-auto-nudge.ps1 -TaskPrompt "你要交給 kilo 做的任務內容"

# 想先用短間隔測試效果
.\kilo-auto-nudge.ps1 -TaskPrompt "測試任務" -CheckIntervalMinutes 5 -IdleAfterMinutes 5
```

跑起來之後,這個 PowerShell 視窗**請保留開著**(不要關閉),它同時扮演
「執行任務的視窗」和「監控/催促」兩個角色。你仍然可以在裡面直接看到
kilo 的所有輸出。

### 重要限制與風險說明(請務必看過)

- 這是**用「畫面多久沒有新輸出」當作代理指標**,不是官方提供的精準狀態
  查詢,所以如果 kilo 正在做「本來就會安靜很久才有輸出」的長任務
  (例如下載大檔案、跑很久的編譯),有可能被誤判成閒置而被催促一下 ——
  但這頂多是多送一行文字進去,不會中斷、也不會刪除任何東西,影響有限。
- 腳本本身**不會執行任何刪除檔案或修改系統設定的動作**,它只讀輸出、
  在偵測到閒置時寫一行文字進輸入管道。實際哪些操作會被允許/擋下,
  仍然由第 2 節的 `kilo.jsonc` 設定決定。
- 若你在 `-ExtraArgs` 裡加上 `--auto`(等同 `kilo run --auto "..."`),
  官方文件指出 `--auto` 會**自動核准所有動作**,這會蓋掉 `kilo.jsonc`
  裡對刪除/系統穩定性設的 `deny`/`ask` 規則。若要保留「刪除檔案、
  影響系統穩定性不自動核准」這個限制,**建議不要加 `--auto`**,
  維持腳本預設值(只用 `run`),讓它依 `kilo.jsonc` 的 permission
  規則逐項核准。
- 因為雲端作業環境無法連上你的實體筆電做實際測試,**第一次使用請先拿一個
  不重要的小任務試跑**,觀察行為是否符合預期,再套用到正式任務上;
  如果偵測門檻(`-IdleAfterMinutes`)或催促用詞(`-NudgePrompt`)
  不合你意,直接調整參數即可。
